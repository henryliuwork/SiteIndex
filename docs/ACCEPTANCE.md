# SiteIndex 桌面端验收脚本规范

本规范落实 v0.8.5 路线图 §3.4 的 H1–H10，定义桌面安装包验收与复用报告的方法，不代表任何版本已通过验收。

## 执行前

1. 固定基线包和候选包的来源、版本、commit、CI run、artifact 标识与预期 SHA256。先核验两个包的哈希；来源或哈希不符时停止并记 harness_error。
2. 只用合成项目与虚构站点，域名限 .example.test；使用隔离 profile 和 APPDATA/LOCALAPPDATA，不读取或复制真实项目数据、凭据或商业数据。
3. 每个设置项用独立会话及 profile。记录合成配置原值并在条目结束后清理。遇 EBUSY 重试；仍失败时单独记录清理状态，不覆盖断言结果。
4. 一次运行只用统一入口与条目范围参数。启动、等待、正常退出和清理逻辑全仓各保留一份，不在页面条目中复制。

## H1–H10

| 规则 | 验收要求 | 失败记录 |
| --- | --- | --- |
| H1 正常退出 | 用 WM_CLOSE 或应用支持的正常退出流程结束应用，并等待进程退出。强制结束只用于明确标为“崩溃恢复”的专项条目。 | 记录退出方式和进程状态。负向自测强杀必须报告 H1 违规。 |
| H2 独立会话 | 每个设置项使用独立会话和 profile，不连续复用前一项 UI 状态。 | 记录合成 profile 编号，不写本机账户名或真实目录。 |
| H3 可观察等待 | 轮询 UI、进程、IPC 或文件状态并设超时；禁止以固定 sleep 推断完成。 | 有效断言已启动但状态未出现，记 assertion_failed；等待器或前置条件不可用，记 harness_error。 |
| H4 稳定定位 | 使用可访问角色与名称或 data-testid；禁止以页面可见文本搜索作为定位器。缺稳定标识时记录脚本阻塞，不用脆弱文本定位绕过。 | 记录定位器类型、控件标识、失败阶段；不直接归因产品失败。 |
| H5 失败产物 | 每个失败保存明确错误消息与堆栈、截图、控制台消息及最近一次 IPC 调用信息。IPC 参数和截图须脱敏；不得只写 Error。 | 关联脱敏证据索引。公开日志不得出现密钥、文件内容或真实项目数据。 |
| H6 合成数据与清理 | 只用合成项目、虚构内容及 .example.test 域名，运行于隔离 profile/APPDATA，条目结束后清理。 | 记录清理结果、重试次数或单独清理失败；不得掩盖断言结果。 |
| H7 统一报告 | 报告结构至少含条目 id、阶段、状态、证据。运行元数据含基线/候选版本、commit、artifact、SHA256 和 OS/runner 标识。 | 字段缺失、结构无法解析或无法关联固定包，记 harness_error。 |
| H8 失败分类 | assertion_failed 表示断言已执行但结果不符；harness_error 表示框架未能可靠执行或取证，如脚本错误、错误定位器、报告写入或清理失败。未运行项记 not_run。 | harness_error 不得当产品缺陷，也不得改写成通过。分类不明时留证交 lead 复核。 |
| H9 包哈希 | 基线包与候选包均先校验 SHA256，分别记录来源、预期值和实测值。 | 哈希不符或来源无法固定时停止安装，记 harness_error / not_run，不判断包行为。 |
| H10 单一入口 | 通过一个可复用工作流按范围与固定版本引用运行，例如 --items 1-83 --baseline <ref> --candidate <ref>。 | 记录实际参数与解析后的范围；禁止页面专用入口或复制启动、退出、等待、清理逻辑。 |

### 最低报告结构

字段名应机器可读且稳定。实现可增加字段，但不得删除最低字段或合并失败类别：

~~~json
{
  "run": {
    "baseline": { "ref": "vX.Y.Z", "sha256": "<verified>" },
    "candidate": { "ref": "vX.Y.Z-rc.N", "sha256": "<verified>" },
    "runner": "windows-hosted",
    "os_build": "<build>"
  },
  "items": [
    {
      "id": "H1",
      "phase": "shutdown",
      "status": "passed",
      "evidence": ["<redacted-artifact-reference>"]
    }
  ],
  "cleanup": { "status": "passed", "retries": 0 }
}
~~~

状态至少支持 passed、assertion_failed、harness_error、not_run。失败 evidence 关联脱敏消息/堆栈、截图、控制台与最近 IPC；未运行项说明阻塞原因。公开报告不含真实 URL、SKU、商品名、价格、Feed、凭据、用户目录或文件内容。

## 必须的负向自测

CI 中注入两种故障并确认报告以 assertion_failed 明确失败：

1. 设置保存操作完成，但设置未写入持久化存储。
2. 应用被强制结束而非正常退出；报告指出 H1 违规。

若未检出注入故障，记录断言失败。若框架自身未运行、定位器失效或无法产出报告，记 harness_error；不得据此修改产品代码。

## 工作流迁移边界

共享启动、正常退出、可观察等待、profile 管理、清理和报告逻辑集中在一个可复用入口。新工作流全量运行前保留旧脚本；只有 G8.5-3 全量运行通过后，才按路线图统一删除旧脚本。本文不证明工作流已实现或 Gate 已通过。
