# SiteIndex · v0.4.x Roadmap：Agent 工作区 + 库存核验 + EDM 图片托管（2026-11-05）

> 本文是 v0.4.x 的**唯一执行计划**。开工前仍须先读 `docs/WORKSTREAMS.md`、`AGENTS.md`，并确认 v0.3.x 路线图（`2026-11-05-v030-roadmap.md`）的契约队列 K0–K3 已合并到哪一步。
> 决策背景见 `docs/decisions/2026-11-05-workspace-template.md`。模板草案见 `docs/plan/2026-11-05-v040-templates-draft.md`。
> 仓库公开：截图、日志、Issue、fixtures 只能用虚构数据（示例域名 `example-shop.test`），不得出现真实商品名、SKU、价格、URL、账号、密码、受众 ID、连接标识、本机路径。

## 0. 一句话目标

1. 创建项目时可一键生成"Agent 工作区"（板块目录 + `README.md` + `AGENTS.md` + `.env` + 数据层 `_site-index/` + 技能），任何 agent 打开项目根目录读 `AGENTS.md` 即可开工。
2. 库存判断更可靠：feed 里消失的 SKU 用产品页核验（404=下架，有页面则判断缺货）。
3. EDM 产品图：webp 在邮件里不显示，由程序转成 jpg，经 WordPress REST 上传，URL 回填 `sku_media` 台账，供 EDM 技能使用。
4. 技能中心内置脱敏后的三个 EDM 技能（`siteindex-edm-plan/build/mc-send`），支持安装到 `~/.agents/skills`。
5. agent 通道：命令行（含 `siteindex mcp`，stdio），读写分组。

## 3. 数据与契约变更

> 契约队列：K0→K1→K2→K3（v0.3.x）合并后才开 K4；K4 合并后才开 K5。同一时刻最多一个 `contract/*` 未合并。

### K4 `contract/v040-workspace`（A 写）
1. `ProjectLayout = "legacy" | "workspace"`；`resolveProjectLayout(projectPath)`：存在 `_site-index/site.json` → `workspace`，否则 `index/site.json` → `legacy`，都没有 → 报错。
2. 路径：`PATHS` 保留为 legacy 常量；新增 `pathsFor(layout)`，返回同一组 key 的路径（workspace 前缀 `_site-index/`，skills 为 `_site-index/skills`）。**代码一律经 `pathsFor(layout)` 取路径，禁止新增裸字符串。**
3. `SiteConfig.workspace?: { version: string; sections: string[]; esp_presets: string[] }`；`SiteConfig.edm?.image_host?: { type: "wordpress" }`（不含凭据）、`edm.discount_tiers?: number[]`；`crawl.stock_verify?: { enabled: boolean; graphql_url?: string; max_per_run?: number }`。
4. API：`workspace.check(targetDir)`（空目录检查，返回不合格条目前 10 项）；`workspace.create(input)`；`projects.createWorkspaceOnly(input)`（空文件夹补建，不抓取）；`workspace.importCheck(projectId)`（返回 `issues[]` 与可自动修复项；`apply` 只补缺、不覆盖）。
5. `CreateProjectInput.workspace?: { enabled: boolean; platform: "magento2" | "woocommerce" | "shopify" | "other"; esp_presets: string[] }`。
6. 设置：`AppSettings.close_to_tray: boolean`、`launch_at_login: boolean`；技能平台预设 id `agents-dir`。
7. 错误码：`WORKSPACE_NOT_EMPTY`。
8. 规则：全部只做加法或可选字段。旧 mock 与旧 fixtures 不变。

### K5 `contract/v040-media-stock`（A 写）
1. `Sku.removed_reason?: "feed_absent_404" | "feed_absent_aged"`；库存事件类型增加 `feed_anomaly`（页面显示有货但 feed 缺失）。
2. 台账 `sku_media`：`source` 枚举增加 `wordpress`；在行尾**追加**可选列 `media_id`、`source_hash`；不改旧文件字节，旧文件首次写入时才升级表头（带迁移测试）。
3. Job：`media`（输入 `skus: string[]`，只处理无 URL 的 SKU；无 `overwrite` 参数）；返回逐 SKU 结果 `{sku, status: "uploaded"|"reused"|"recorded"|"skipped_has_url"|"failed", reason?, image_url?}`。`recorded` 表示原图可直接登记，无 WordPress 上传。
4. API：`media.prepare({ project, skus })`。
5. 错误码：`WP_NOT_CONFIGURED`、`WP_AUTH_FAILED`、`WP_FORBIDDEN`、`WP_REST_UNREACHABLE`、`IMAGE_DECODE_FAILED`、`IMAGE_FETCH_FAILED`。
6. `edm export-index` CLI 命令本身与 `siteindex mcp` 不进 K5；UI 调用入口由 #423 的独立 shared 契约补充。
7. #422 恢复字段作为后续加法补充到 `JobResult` / `RunLog`：保留去重后的请求顺序、已确认逐 SKU 结果、未知与未开始列表、批次状态和认证错误码；旧历史缺少这些字段时结果不可恢复，不能推断为空。

## 4. 关键设计

### 4.1 工作区创建（core `workspace.create`）
1. 空目录检查：忽略集合见 D4；不空 → `WORKSPACE_NOT_EMPTY`，只列出前 10 个不合格条目名。
2. 渲染模板（`templates/workspace/`，变量：品牌名、域名、平台、目标市场、日期；缺值留空，不写"待补充"外的猜测）。
3. 写入：根文件、七个板块 README 与子目录（空目录写 `.gitkeep`）、`_outputs/_archive/_tmp`（带简短 README）、`.gitignore`、`.env` 模板（不存 WordPress 上传凭据）、`_site-index/site.json`、`workspace.json`、`skills/`。
4. 刷新自动区块（README / AGENTS.md）。
5. 失败回滚：只清理本次创建的文件；返回创建清单。
6. `projects.createWorkspaceOnly`：用户填域名、平台、品牌名，生成上述全部内容但不抓取；之后用户手动复制旧数据，再点"导入检查"。

### 4.2 导入检查
- 对象：`_site-index/` 内容。校验 `site.json` 位置与 `schema_version`、各表文件是否存在与格式、台账表头、`workspace.json` 与 `site.json.workspace` 是否缺失。
- 可自动修复：缺失的空台账文件、缺失的 `workspace.json`、缺失的自动区块；**不覆盖**任何已有文件。
- 缺失的根目录 `CLAUDE.md` 也列为可自动修复项，并从工作区模板独占创建；已有文件无论内容如何都保留原样。
- 旧数据复制进来后会覆盖生成的 `site.json`（旧文件没有 `workspace` 块）：由导入检查补上。

### 4.3 README / AGENTS.md 的自动区块
- 沿用 `<!-- siteindex:auto:start id="…" -->` 标记语法。
- README：`workspace-map`（来自 `workspace.json`）、`index-summary`、`changelog`；其余为用户区。
- AGENTS.md：`agents-core`（身份与数据层规则）、`task-routing`、`data-guide`、`design-summary`、`skills-installed`、`esp-presets`（已启用的渠道预设）；"项目约定与变更记录"为追加区，**agent 不直接改 AGENTS.md，提案写入 `_outputs/agents-md-proposals.md`，用户确认后合并**。
- `readme` Job 同时刷新两份文件；`legacy` 布局保持原有五个区块与 README 单文件结构。

### 4.4 EDM 数据
- `siteindex edm export-index <p>`：从 `views/products`（按 `sku_grouping` 聚合到父 SKU）+ `ledgers/sku_media` + `ledgers/sku_tags` 生成布局固定清单：workspace 为 `_site-index/edm/sku-index.md`，legacy 为 `index/edm/sku-index.md`。字段、确定性、生成标记、冲突保护及旧台账兼容以 `docs/DATA_SPEC.md` §3.1 为准。折扣价按 `edm.discount_tiers` 计算；短描述取 `sku_tags.email_blurb`。
- 图片选择：`sku_media` 台账优先（`image_role=main`），其次 feed 首图；jpg/png 可直接使用；webp 不得出现在 EDM 清单里，没有可用图的 SKU 在清单里标"待补图"。
- 台账键为 SKU；选中父 SKU 时落到代表子 SKU（第一个有货子 SKU，同状态取字典序最小），父行显示代表子 SKU 的图。
- 首期导出范围固定为全项目 canonical 清单，不接收 SKU 子集或调用方输出路径。D 的 mock 原型中“当前选中 SKU 独立副本”是后续提案，不是本期功能。
- `window.siteindex.edm.exportIndex(projectId)` 是可选 UI/IPC 能力以兼容旧 bridge，只能返回布局允许的安全相对路径、导出状态及计数。冲突返回 `EDM_INDEX_CONFLICT` 且保留无生成标记文件；写入后无法确认响应时返回 `EDM_EXPORT_OUTCOME_UNKNOWN`，不报告为确定失败。当前 Core/CLI、Desktop IPC/preload 与 EDM UI 真实入口尚未实现此能力。
- 导出实现按项目串行化 SiteIndex 自身写入；首次创建和更新都需在写锁内重新读取目标，并在暂存后复核真实项目根目录、全部祖先组件、目标身份/标记/内容指纹。祖先 symlink/junction 越界、目标在检查后被新建或替换、身份或内容不一致时必须 fail closed，返回冲突/未知并保留用户文件。普通“复核后 rename”不是 no-clobber 或 compare-and-swap：跨进程在最后复核与替换之间仍存在竞态窗口。只有当前平台和文件系统提供并经测试验证的 no-clobber 创建/条件替换原语，才能承诺该窗口内也不会覆盖；否则拒绝写入，禁止用无条件 rename 降级。具体边界以 DATA_SPEC §3.1 为准。
- Email History 回写改为写 `ledgers/edm_campaigns`，不再编辑清单文件。
- `siteindex edm render` 标记为 deprecated，保留不删。

### 4.5 图片托管（WordPress）
```
选中 SKU（EDM 页多选 / media.prepare / MCP）
 └ 已有 URL？→ skipped_has_url
 └ 解析代表 SKU 与源图（feed 图 / 台账）
    ├ 源图为 jpg/png → 直接记录 URL（source=cdn），不上传
    └ 其他格式（webp/avif…）
        ├ 下载（遵守 rate_limit_ms）
        ├ WASM 解码；带透明通道则铺白底
        ├ 长边 ≤ 1200，保持比例，不放大，不加边；jpg 质量 85
        ├ 文件名 {sku小写}-main.jpg；上传前 GET /wp/v2/media?slug= 查重，已有则复用（reused）
        ├ POST /wp-json/wp/v2/media（Basic：用户名 + 应用密码）；再设置 title / alt
        └ 取返回的 id 与 source_url → 写台账（source=wordpress, media_id, source_hash）
```
- WordPress 上传凭据仅存本机，不写入项目根 `.env` 或其他云盘同步文件。由程序读取，**不进入任何日志、IPC 返回、CLI/MCP 输出、导出文件**；实现前明确 Windows/macOS 本机存储方案、凭据缺失与换机提示，以及已有 `.env` 凭据的安全迁移方式。原有 `.env` 的忽略规则仍保留。
- 单个 SKU 失败不中断整批；401/403 立即停整批并返回明确错误码，提示用户检查应用密码或账号是否有上传权限。
- 转换使用 WASM（建议 `@jsquash/webp` + `@jsquash/jpeg`；A 在 W0 做 spike 后定），不引入原生模块。
- 转换缓存放 `{cache_dir}`；上传成功后可删除。

### 4.6 库存核验
- 位置：`daily` Job 合并 feed 之后。
- 候选：本次 feed 中缺席的 active SKU。若 feed 为空或缺席比例超过 `max_removed_ratio`，**整步跳过**（与现有保护阈值一致，不核验）。
- 每个候选请求其 `url`：
  - 404/410 → `status: removed`，`removed_reason: feed_absent_404`；
  - 200 → 按核验器判断：缺货 → `out_of_stock`；有货 → 保持 `missing_as` 之外的状态并记 `feed_anomaly` 事件与一条 SEO 外的数据 issue（"feed 缺失但页面有货"）；无法判断 → `unknown`，沿用 `missing_as`；
  - 网络失败、5xx → 本次不改状态。
- 核验器链：`magento-graphql`（优先；`crawl.stock_verify.graphql_url` 缺省时尝试同域 `/graphql`）→ `page-text`（用 `crawl.stock_rules` 的文案匹配）。
- 上限：`max_per_run`（默认 50），遵守 `rate_limit_ms`。
- 平台适配以 Magento 2 为主；WooCommerce / Shopify 本轮只在文档说明，不做核验器。
- 测试只用本地静态 fixture 与伪 GraphQL 服务；真实站点探测由 E 在用户本机做，只回报脱敏结论。

### 4.7 调度与托盘
- Windows 任务计划为主，托盘常驻兜底（保持现状）。
- 设置新增：
  - `close_to_tray`（默认开）：关闭窗口时最小化到托盘而不是退出；关闭该开关后点关闭即退出；
  - `launch_at_login`（默认关）。
- 托盘菜单：打开、下次计划、立即同步、退出；退出时若有运行中的 Job 需二次确认。

### 4.8 `siteindex mcp`
- 命令：`siteindex mcp --project <路径>`，stdio，随 agent 启动；基于官方 MCP SDK（新增依赖需同 PR 更新 `pnpm-lock.yaml`）；stdout 只输出协议内容，日志走 stderr。
- 只读组（默认开）：`project_info`、`query`（products、sku-stock、seo-pages、seo-issues、blog、keywords、sku-media）、`validate_report`、`job_status`、`edm_export_index`（读取导出结果）。
- 写入组（默认关，需 `--allow-write` 或项目配置显式开启）：`ledger_upsert`、`ledger_delete`、`run_job`、`media_prepare`。
- 所有写入遵守运行锁与执行设备规则；`.env` 与凭据永不出现在任何返回里。
- **工具清单与参数在 PR 描述里列表供用户审阅，用户确认后再合并。**

### 4.9 技能
- 内置新增：`siteindex-edm-plan`、`siteindex-edm-build`、`siteindex-edm-mc-send`（起始版本 `1.0.0`），脱敏规则：
  1. 删除品牌名、域名、受众 ID、连接标识、账号、邮箱、色值、字体、具体 SKU、具体文章 slug、变更记录中的项目事件；
  2. 路径一律通过 `_site-index/workspace.json` 的逻辑名取得，不写 `03-edm\` 等硬编码；
  3. `{sku_index_path}` 指向 `_site-index/edm/sku-index.md`；Email History 改写 `edm_campaigns` 台账；
