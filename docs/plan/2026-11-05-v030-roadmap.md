# SiteIndex · v0.3.x Roadmap：界面规范化 + 父子 SKU 全面适配（2026-11-05）

> 来源：用户对 v0.1.9 的 14 项实测反馈。本文是 v0.3.x 的**唯一执行计划**，取代 `2026-10-30-v020-wave2-execution.md` 中仍未完成的 UI 条目。开工前仍须先读 `docs/WORKSTREAMS.md` 与 `AGENTS.md`；本文件只说"这一轮做什么、谁做、什么顺序、怎样算完成"。
>
> 仓库公开：截图/日志/Issue 只能用虚构 mock 数据或脱敏结构，不得出现真实商品名、SKU、价格、URL、本机路径。

## 0. 一句话目标

1. 先把**界面规范**定死（字体、字号、间距、组件、表格、抽屉、通知、右上角按钮区），之后所有页面只能"用规范"，不能再自创样式。
2. 把**表格**统一成一个标准：页面不滚动，表格内部滚动，底部有"每页条数 + 分页"。
3. 把**父/子 SKU** 作为全局能力：所有涉及 SKU 的表格都有"仅显示父 SKU"，产品页的"有货变体"只对父 SKU 有意义。
4. 修掉实测发现的缺陷：计划任务核验误报、SEO 表格按钮点不了、设计页抓取内容不对。

## 3. 界面规范 v2（B 负责落地到 `docs/DESIGN.md` 与 `tokens.css`；以下为基线，B 可微调数值，但必须在 B-0 PR 里写死）

### 3.1 字体与字号

- 字体：`"Geist Variable"`（正文/标题），`"Geist Mono Variable"`（SKU、URL、路径、数字等宽）；中文回退 `"Microsoft YaHei UI", "PingFang SC"`。字体文件随包打包，不依赖网络。
- 字号阶梯（**只允许用这几个 token，页面 CSS 不得再写裸 px 字号**）：

| token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `--fs-page-title` | 20 / 28 | 600 | 页面标题（项目名、"Skill 中心"） |
| `--fs-section-title` | 15 / 22 | 600 | 区块/卡片标题 |
| `--fs-sub-title` | 13 / 20 | 600 | 子区块标题、Drawer 内分组标题 |
| `--fs-body` | **12** / 18 | 400 | **默认正文**、表格单元格、按钮、输入框 |
| `--fs-caption` | 11 / 16 | 400 | 辅助说明、表头小字、徽标 |
| `--fs-kpi` | 24 / 30 | 600 | 指标数字 |
| `--fs-mono` | 12 / 18 | 400 | 等宽内容 |

- 表头 12/600，muted 色；对比度 ≥ 4.5:1（`--color-faint` 已提到 #626D78，沿用）。

### 3.2 间距、圆角、阴影、颜色

- 间距只用 4 的倍数：`--space-1..8 = 4/8/12/16/20/24/32/40`；页面内边距 `24`；卡片内边距 `16`；表单项间距 `12`；区块间距 `16`。
- 圆角：按钮/输入/筛选 `6`，卡片 `8`，Drawer/弹层 `12`，chip `999`。
- 阴影只有两档：`--shadow-pop`（弹层/下拉）、`--shadow-drawer`（抽屉）。
- 颜色沿用 `tokens.css` 现有语义色；**页面 CSS 不得出现裸色值**（`#xxxxxx`/`rgb()`），只能 `var(--color-*)`。新增颜色先改 tokens。

### 3.3 基础组件规格（B 在 `components/` 落地，D 只能使用）

| 组件 | 规格要点 |
|---|---|
| Button | 高 32（小 28）；类型：`primary`（每个区域最多 1 个）/ `secondary`（默认）/ `ghost` / `danger`；图标按钮必须有 `aria-label` + tooltip |
| Input / Select / Checkbox | 高 32；聚焦环统一；**下拉统一用 Radix Select/Popover**，不用原生 `<select>` |
| FilterBar | 下拉优先于 pill；超过两行折叠（已有） |
| Chip | ok/warn/danger/info/neutral，12/600→改用 `--fs-caption`；"处理状态"等状态列统一用 Chip |
| Card / KpiCard | 卡片标题 `--fs-section-title`；KPI 数字 `--fs-kpi`；可点击卡片有 hover 与 focus 态 |
| **Drawer** | 右侧滑出，宽 480（宽内容 720）；顶部标题+关闭；内容区独立滚动；Esc 关闭；焦点陷阱；用于：行详情、规则设置、库存趋势/分类、配置类面板 |
| **Toast** | 全局右上角堆叠，成功 3s 自动消失，错误需手动关闭；**取代页面内"已保存/失败"文字** |
| **Notice** | 页内横幅（info/warn/error），放在内容区顶部卡片内，带图标和可选操作；用于"需要重新抓取""配置变更后未生效"等持续性提示 |
| EmptyState | 图标 + 原因 + 下一步按钮 |
| DataTable | 见 §3.6 |

### 3.4 页面骨架与右上角操作区（`PageHeader`）

- 项目页统一骨架：`项目头（名称/站点/同步状态）→ Tabs → 页面操作栏 → 内容`。右上角为**页面级操作区**，规则：
  - 最多 **1 个主按钮**（primary）+ **最多 2 个次按钮**；其余进"更多 ⋯"菜单；
  - 放这里的：影响整页的动作（立即同步/重新抓取、导出、打开设置类 Drawer、查看图表 Drawer、复制 agent 指令）；
  - **不放这里**：针对某一行的动作（放表格行/Drawer）、筛选（放表格工具栏）、列设置（放表格右上）。
- 通知：操作结果一律 Toast；持续性状态用 Notice；**禁止**把状态文字直接渲染在标题下方。

### 3.6 表格标准（所有 DataTable 统一，**不再允许页面自定义表格容器**）

1. **页面窗口永不纵向滚动**。表格页：工具栏（搜索/筛选/列设置）固定 → 表头 sticky → **表体内部纵向滚动** → 底部固定分页栏。非表格页（概览、设置、README）：内容区自己滚动，窗口不滚动。
2. 底部分页栏：左侧"显示 a–b / 共 N 条"；右侧**每页条数选择：50 / 100 / 200 / 全部**（默认 50，按 `tableId` 持久化到 ui-state）；超过则分页；选"全部"时不分页，必须启用行虚拟化。
3. 表头列宽契约沿用 `ColumnDef.meta`（width/grow/minWidth/align/text）；行高固定且与虚拟行高一致（单行 40，两行省略 52）。
4. 支持右侧固定的**操作列**（`meta.sticky: "right"`）与可选**行选择列**（批量操作）；操作列按钮必须可点击且不触发行点击（`stopPropagation`），并有回归测试。
5. 行点击 → 打开 Drawer（不是挤占表格宽度的右侧面板）。
6. 表格最小高度 320；窗口很矮时表格仍保持最小高度，整体由内容区滚动作为兜底。

## 4. 各工作流任务清单

- **A-5 设计 Token v2（K3 + 提取）**：重写 `jobs/design.ts` 的采样：

## 6. 样式验证：`pnpm ui:check`（B-3）

目的：让每个 UI PR 都有**客观的布局证据**，不靠肉眼和不稳定的截图基线。

- 位置：`packages/ui/visual/`，使用已有的 `playwright-core`（devDependency，沿用 core 已使用的版本）+ 本机 Edge/Chrome（`channel: "msedge" | "chrome"`），不下载浏览器。启动 `vite`（mock 数据）后遍历全部路由。
- 视口：1280×800、1920×1080。
- 断言（失败即非 0 退出）：
  1. `document.scrollingElement.scrollHeight <= clientHeight`（窗口无纵向滚动；非表格页允许内容区滚动）；
  2. 无横向溢出（`scrollWidth <= clientWidth`），`<th>/<td>` 无文字被裁切到不可读；
  3. 表格页：存在 `.si-table-scroll` 且 `overflow-y: auto`，其底部在视口内；底部存在分页栏与"每页条数"控件；
  4. `getComputedStyle(body)`：`font-size = 12px`，`font-family` 首项为 Geist；
  5. 页面样式里**无未登记的字号/颜色**：扫描所有加载样式表，除 `tokens.css` 外出现裸色值或 `font-size:` 裸 px 则告警（先告警，W2 末改为失败）；
  6. 控制台无 error；
  7. 对"可点击的行内按钮"做 `elementFromPoint` 命中检查（防止被浮层遮挡，复现 #4 类问题）。
- 输出：`.shots/<route>-<w>.png`（git 忽略）+ `.shots/report.json`（每页的指标与失败项）。**截图只含 mock 虚构数据，可以贴到 PR；agent 不能看图时用 `report.json`。**
- 不进三系统 CI（Edge/Chrome 环境不稳定），作为 PR 作者必跑项；E 在 Release 后同样运行一次。
