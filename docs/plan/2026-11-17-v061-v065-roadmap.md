# SiteIndex · v0.6.1–v0.6.5 Roadmap：UI 细节收口与 WooCommerce 全面支持（2026-11-17）

> 基线：`v0.6.0` 已于 `c554892` 封版（产品管理与库存合并、样式基线归零、安装包离线字体与 `#480` `--run-job` 通过 77/77）。本文为 `v0.6.1`–`v0.6.5` 唯一执行计划。
> 仓库公开：**严格禁止**在代码、测试、fixture、PR 或文档中出现任何真实站点域名、URL、商品或抓取原始数据；全部测试与示例一律使用虚构域名（如 `example.test`）。

## 0. 代码诊断结论（根因定位）

### A. UI/UX 遗留问题
1. **项目导航与页头横向滚动条**：`packages/ui/src/components/project-header.css` 对 `.si-tabs` 与 `.si-project-header-actions` 显式开启了 `overflow-x: auto` 与 4px 滚动条，未实现窄窗口向“更多 ⋯”的自动收纳。
2. **表格顶部操作区布局散乱**：各页自成一套排法（如 `SeoPage` 将 `Segmented`、`FilterBar`、批量操作按钮、`SearchInput` 挤在一行；`ProductsPage` 与 `ContentPage`/`EdmPage` 也缺乏统一左右分区）。
3. **页面冗余文案偏多**：向导、设置页及部分业务页保留了过多内联副标题与操作解释文字，缺少共享 `<InfoTooltip>` 原语（`@radix-ui/react-tooltip` 已在依赖中，无需新增包）。

### B. WooCommerce 站点同步失败根因（读码排查）
1. **为什么“有 Feed”或“无 Feed”都容易触发 `Feed 快照为空，未写入数据`**：
   - `projects/detect.ts` 的 `feedLinks()` 会把首页 HTML 里任意 `<link rel="alternate" type="application/rss+xml|atom+xml">` 都抓进 `feed_candidates`，而 `NewProjectWizardPage` 直接自动回填 `feedUrls`。在 WordPress/WooCommerce 站点上，这些链接通常是**博客 RSS（如 `/feed/`、`/comments/feed/`）**，并非 Google Merchant Center 商品 Feed。
   - `crawl/gmc-feed.ts` 只认 `<item>`/`<entry>`，且 `toSnapshot()` 硬性过滤 `basePrice === null || !url`。遇到误填博客 RSS、B2B 询价型无价格商品、或部分插件的 XML 根节点（如 `<products><product>`），所有条目被静默过滤，最终 `snapshot.length === 0` 触发 `Feed 快照为空，未写入数据`，且未提示过滤统计（`no_id` / `missing_price_or_link`）。
   - 无 Feed 时 `init` 与 `daily` 直接 `skipped`，没有任何从站点自动采集商品写入 `skus.jsonl` 的回退路径。
2. **为什么报错 `categories 结果为空，未覆盖现有数据`**：
   - `jobs/weekly.ts` 的 `categories()` 在 `feed` 模式下完全依赖 `skus.jsonl`；当 Feed 为空或无 Feed 时必为空。
   - 在 `url_rule` 模式下，`pageType()` 对分类页识别偏向 `/collections?/`、`category` 等固定词；当 WooCommerce 自定义分类前缀（如 `/shop/<slug>/` 或自定义多前缀）或 `detect` 未自动探测 `/sitemap_index.xml` / `/wp-sitemap.xml` 时，`collection` 页识别不到，`categories` 同样为空。
3. **变体与跨板块断层**：
   - WooCommerce 可变商品（Variable Product）带 `?attribute_pa_*=` 参数链接时，需要在 SEO 侧规范归并到主商品 URL，同时在产品管理侧以父商品 + 子 SKU 变体进入既有父子视图。
   - WordPress 博客 Sitemap（`post-sitemap` / `wp-sitemap-posts-post-*`）、WooCommerce Store API、图库与缺货核验均未针对性适配。

## 2. 分版本详细要求与工作流边界

### v0.6.1 · UI/UX 精细收口（当前优先）

1. **项目导航与页头零横向滚动条（B）**
   - 修改 `ProjectHeader`（`project-header.tsx` / `project-header.css`）：移除 `.si-tabs` 与 `.si-project-header-actions` 的 `overflow-x: auto` 及滚动条样式；改用容器宽度测量（`ResizeObserver`），按可用宽度将放不下的 Tab 动态收纳到“更多 ⋯”下拉菜单（当前激活 Tab 尽量保持可见或在收纳入口高亮），右侧页头操作同理按规范保留 `≤1` 主按钮 + `≤2` 次按钮 + “更多 ⋯”。
   - 更新 `ui:check`：在 1024×768、1280×800、1440×900、1920×1080 视口下检查 `.si-project-header .si-tabs`、`scrollWidth <= clientWidth` 及各页面无水平溢出/控件挤压。

2. **共享 `<InfoTooltip>` 与全站文案精简（B 共享层 + 应用级页；D 项目业务页）**
   - **规范已写入** `AGENTS.md` 与 `docs/DESIGN.md`：`Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.`
   - **B** 基于已安装的 `@radix-ui/react-tooltip` 实现 `<InfoTooltip label="..." content="..." />`（圆形 `i` 图标按钮，hover/focus 触发，气泡最大宽 ≤ 240px，单测覆盖键盘与悬停可访问性），并精简 `NewProjectWizardPage`、`AppSettingsPage`、`ProjectCenterPage`、`SkillsPage`、`ReadmePage` 中的大段说明文字与多余副标题。
   - **D** 逐页精简 `OverviewPage`、`ProductsPage`、`SeoPage`、`ContentPage`、`EdmPage`、`DesignPage`、`RunsPage`、`ProjectSettings*Page` 的冗余副标题与描述文本，必要解释收进 `<InfoTooltip>`。

3. **表格顶部工具栏统一（方案 A）（B 规范与共享骨架；D 业务页迁移）**
   - 视角切换 `Segmented` 单独前置左对齐；工具栏固定“左：搜索 + `FilterBar`（>2 行可折叠） / 右：视图开关 + 列设置 + 统计计数”。
   - 整页动作（立即同步、运行、导出、规则设置等）**全部收归右上角页头**；例如 `SeoPage` 筛选条内的“批量处理当前筛选结果”移入勾选行工具栏或页头更多；`ProductsPage`、`ContentPage`、`EdmPage`、`ProjectTodosPage`、`SeoPage`、`RunsPage` 统一对齐。
   - 批量操作仅在勾选行后展示。

4. **并行与合入顺序（v0.6.1）**
   - B 先做 **PR1：ProjectHeader 溢出收纳（去滚动条）+ `<InfoTooltip>` + 共享 `TableToolbar` + `ui:check` 溢出检查**；合入后 B 做应用级页面精简，D 同步做项目页工具栏对齐与文案精简；E 完成 `v0.6.0`（`#576`）终验后将新发现一并纳入 `v0.6.1` 修复。

### v0.6.2 · WooCommerce 探测、Feed 诊断与自定义分类前缀

1. **智能探测与区分博客 RSS（A + B）**
   - `projects/detect.ts`：识别 `<link rel="alternate">` 时排除博客/评论 RSS（如 `/feed/`、`/comments/feed/`、`wp:posts` 等），只在候选包含真实商品 Feed 特征时入列；未发现明确商品 Feed 时明确提示“未配置商品 Feed，将使用站点自动采集（Store API / Sitemap）”，不再误把博客 RSS 填进向导的 GMC Feed 输入框。
   - Sitemap 探测自动顺序检查 `robots.txt`、`sitemap_index.xml`、`wp-sitemap.xml`、`sitemap.xml`（适当放宽子 Sitemap 索引探测上限，只读解析索引，不阻断大站），标注 WooCommerce 常见的商品/分类/文章子 Sitemap。
   - **自动反推自定义分类前缀**：从分类子 Sitemap（如 `product_cat-sitemap*`、`wp-sitemap-taxonomies-product_cat*`）和商品 URL 路径结构中自动归纳分类前缀模式（支持 `/product-category/{slug}`、`/shop/{slug}`、自定义多级/多前缀），作为推荐 `url_pattern` 返回给向导与设置页。

2. **Feed 透明报错与容错（A + 若需契约字段则走 `contract/*`）**
   - `crawl/gmc-feed.ts` 与 `daily`/`service`：`toSnapshot` 返回过滤统计（`no_id`、`missing_price_or_link`、`duplicate` 等）；当有效快照为 0 时，`daily` 错误信息明确写出命中原因（如“解析到 N 条记录，但均缺少价格或链接 / 疑似博客 RSS 而非商品 Feed”）。
   - 支持常见 WooCommerce Feed XML 结构变体（如 `<products><product>` 或兼容字段映射）以及 B2B/询价型无价格商品策略（是否允许 `price: null` 入库由独立 `contract/*` 评审确认，确保不破坏既有黄金测试与 `schemas/` 校验）。

3. **多前缀配置 UI（B 向导 + D 项目设置）**
   - 新建向导与项目设置分类页支持**逗号分隔多前缀 / 多个 URL 规则**与**自动识别预览**，在 UI 上直观显示“将匹配到哪些分类前缀”，避免用户手动猜正则。

### v0.6.3 · WooCommerce 无 Feed 商品采集与 Daily / 库存 / 变体闭环

1. **无 Feed 商品采集链（A）**
   - **主通道（Store API）**：探测并分页抓取 `/wp-json/wc/store/v1/products`（与 `/wp-json/wc/store/v1/products/categories`），提取商品 ID、SKU、父子变体（Variable / Variation）、价格、促销价、货币、库存状态（`is_in_stock` / `is_on_backorder` / `is_purchasable`）、主图、分类与商品 URL。
   - **回退通道（Sitemap + HTML）**：当 Store API 被关闭/403/404 时，按商品 Sitemap（或识别到的商品 URL）抓取页面 `application/ld+json`（`@type: Product` / `Offer` / `ProductGroup`）与 WooCommerce DOM（`.sku`、`.stock`、`.woocommerce-product-gallery`、面包屑），生成同构商品快照。
2. **接入 `init` 与 `daily`（A）**
   - 当站点未配置 GMC Feed 时（且平台为 `woocommerce` 或启用自动商品采集），`init` 与 `daily` 调用无 Feed 采集器生成标准 `FeedSnapshot`，照常写入 `skus.jsonl`、`inventory/latest.jsonl`、库存/价格变动事件、30 天状态与 `daily_summary.csv`，并触发 `buildViews`，让产品管理、库存统计、EDM、概览全部正常出数。
3. **父子 SKU 与实时缺货核验（A）**
   - Variable Product 的主商品作为父行（`product_id` / `parent_sku`），各 Variation 作为子 SKU 行，天然融入 `v0.6.0` 已合并的父子 SKU 视图（父行显示价格区间与 `有货变体 x/y`）。
   - `stock-verifier.ts` 扩展支持 WooCommerce（Store API 单品查询或页面 JSON-LD 库存核验）。

### v0.6.4 · WooCommerce 全板块适配（Weekly / SEO / 内容 / EDM / 设计）

1. **Weekly 分类与页面分类（A）**
   - 支持自定义多前缀 `url_rule`；在 WooCommerce 模式下即使 `skus.jsonl` 尚未先跑 `daily`，也能结合 **Store API 分类接口 + 分类 Sitemap + 分类页/面包屑 HTML** 生成完整的 `categories.json`（含父子层级 `parent` 与准确计数），彻底消灭 `categories 结果为空` 假失败。
   - `pageType()` 识别自定义商品前缀与自定义分类前缀；对带 `?attribute_pa_*=` 等变体查询参数的商品链接，**在 SEO 页面规范归并（canonicalize）到主商品 URL**，避免同商品被拆成大量重复页面与假性重复标题/缺失告警，而在产品管理页仍保留子 SKU 变体明细。
2. **内容 / 博客与 EDM / 设计 / README 适配（A + D）**
   - WordPress 博客 Sitemap（`post-sitemap*`、`wp-sitemap-posts-post-*`）及文章 DOM/REST 自动识别纳入内容板块，确保文章收录、内链到商品、缺货提醒与博客 Schema 检查可用。
   - 核对 WooCommerce 商品主图/图库抓取、EDM 选品与导出、设计规范提取（含常见 WordPress/WooCommerce 主题样式变量提取）及 README 自动区块渲染。
   - D 侧配合检查各业务页对无价格（询价）/无 Feed 来源标签的展示兼容性（如有缺失用 `--` 或“询价”等明确表示，不报错）。

## 3. 波次依赖与执行原则

1. **顺序与并行**：`v0.6.1`（B 共享层 PR1 → B/D 全站页面收口 + E 验 `v0.6.0`）先行；同时 A 可启动 `v0.6.2` 的 Core 探测与 Feed 诊断设计/实现（只改 `packages/core/` 时与 B/D 零文件冲突，需改 `packages/shared/` 时单独走 `contract/*` PR）。
2. **严守公开仓库红线**：所有 PR、测试、fixture、截图与 issue 评论严禁出现任何真实站点的域名、URL、商品或日志原文。
3. **不越界、小步 PR**：每个 PR 控制在 ≤ 600 行，严格按工作流目录边界提交，三系统 CI 全绿后由协调者合并。
