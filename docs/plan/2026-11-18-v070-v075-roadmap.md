## 3. 板块页面规范（v0.7.5 的核心交付，B 在 W0 写入 `docs/DESIGN.md` 与 `AGENTS.md`）

### 3.1 页面骨架（自上而下，且仅此顺序）
1. `ProjectHeader`：项目名、域名、**唯一的"最近同步"时间**、项目导航 Tab、页头操作。
2. **一行摘要 `SummaryLine`（可选）**：见 3.2。
3. 工具栏：左 搜索 + 筛选；右 视图开关 + 列设置 + 计数（沿用 v0.6.1 方案 A）。
4. 表格（DataTable v2）。
5. 行抽屉：详情、问题、内链、变更等全部在这里。
6. 条件横幅：只在"有进行中任务 / 失败 / 需要你处理"时出现，其余时间**不占位**。

### 3.2 一行摘要 `SummaryLine`（B 新建共享组件）
- 单行，最多 4 项，每项 = 标签 + 数字；**每项可点击**，点击即把对应筛选应用到下方表格（再点取消）。
- 不得出现纯描述性数字（如"抓取页面 414"）。只放"需要行动"或"变化"类数字。
- **同一个数字只能出现一次**：摘要里出现了就不得再在 Tab 徽标、表格上方文字里重复；表格的总数计数属于工具栏，不算摘要。
- **时间规则**：页面内不直接展示数据时间。若某板块数据来源的时间与项目"最近同步"不同（如 SEO 抓取），把它放进摘要行末尾的 `<InfoTooltip>`（"SEO 抓取于 MM-DD HH:mm"）。同一页可见时间文本 ≤ 1 处（页头）。
- 窄窗口：摘要项过多时收纳进"更多 ⋯"，不得换行成第二行、不得横向滚动。

### 3.3 视图与 Tab 判定规则
- **同一行实体 → 合并**：同一个对象的不同属性（页面的问题、内链、收录）不得拆成多个页内 Tab，改为**列 + 行抽屉分段**。
- **不同实体 → 才允许页内分段**：如"博客文章 / 关键词映射"。分段切换不得清空其他页面状态，**分段上不显示计数徽标**。
- 页内分段不得出现在表格"内部"的联动（点分段 → 表格列与筛选整体重置）。如果切换需要重置，说明它们应该是两个路由级页面或合并。
- 抽屉内的分段（如产品管理已有的"概况 / 变体库存 / 历史"）允许使用。

### 3.4 概览页
- 概览是项目首页，**保留指标卡**，但每张卡必须点击跳转到对应板块的已筛选视图，否则删除；卡片总数 ≤ 6；卡片文案不得与项目头重复。

### 3.5 可量化指标（`ui:check` 在 7.5 W0 增加断言，违反即失败）
| 指标 | 阈值 |
|---|---|
| 1280×800，板块页（无条件横幅时）表格表头顶边距视口顶部 | ≤ 200px |
| 1280×800，首屏可见数据行（行高 52px） | ≥ 9 行 |
| 同一页面可见 `formatDateTime` 形态文本 | ≤ 1 处（页头） |
| 板块页内分段组数量（不含抽屉内） | ≤ 1 组，且无计数徽标 |
| 含"今天 / 昨天"的可见文本 | 0 |
| 横向滚动条（1024×768 ~ 1920×1080） | 0 |

阈值只在 B 的 W0 PR 内、以实测基线核对后可**下调严格度**，上调须经 lead 记录原因。

### 3.6 各页落地目标（D 在改造前先交"合并矩阵"，lead 对照本节评审）
- **SEO**：主体是**页面表**。列：标题 / URL、页面类型、收录状态、待处理问题数（按严重度）、内链入出、最近变化。默认排序：高优先级待处理问题数降序，其次本次新增。摘要项建议：待处理问题 · 本次新增 · 未收录 · 已修复。行抽屉分段：问题（含"标记已处理/忽略"）/ 内链 / 收录。批量处理：勾选页面后"标记所选页面的待处理问题"，必须经确认弹窗并写明条数。旧"问题清单""内链列表"视图删除，不留重复入口。
- **内容**：博客识别摘要、最近识别时间、KPI 合并为一行摘要；"博客 / 关键词映射"为不同实体，可保留一组分段（无计数徽标）；博客识别配置入口收到页头"更多"。
- **EDM**：KPI 收为摘要；"任务与提示"区改为条件横幅；导出控件进页头；表格直接位于第一屏。
- **产品管理**：5 张 KPI 收为摘要（在线率 · 今日变化 · 长期缺货 · 状态波动）；保留 v0.6.0 已合并的单表与抽屉分段。
- **概览**：见 3.4。

## 4. v0.7.0 任务清单

### 4.1 总体原则
- 9 个方法 = 3 组 × 3，**一组一个 PR 序列**，可并行；每组遵循"IPC 接线 → 退出 `PENDING_HANDLERS` → 界面入口 → 打包验收"。
- 界面入口一律做成**行抽屉内的分段**（A3），写成独立新文件（如 `pages/seo/drawer/*`、`pages/products/drawer/*`、`pages/edm/drawer/*`），业务页仅增加挂载点。
- 全部为**只读查询**（`ScenarioQueryResult`），本轮不新增写入能力。

### 4.2 A · Core（`packages/core/`、`packages/cli/`、`fixtures/`、`schemas/`）
- A-0：核对 9 个方法的返回结构与 `shared` 契约一致；列出契约缺口（有缺口则**一个** `contract/v070-scenario-queries` PR，且排在 K 队列首位）。
- A-1：为 9 个方法补黄金夹具与边界测试（无数据、单页缺失、超大项目分页上限）。
- A-2：9 个方法在 1 万 SKU / 5 万页面合成数据下的耗时记录（只记录，不做优化，优化进 backlog 除非超过 §6 的性能线）。
- 不做：新增抓取逻辑、新增规则。

### 4.3 C · Desktop（`packages/desktop/`、`.github/workflows/`）
- C-1：在 `ipc` 注册 9 个 handler，转接 Core service；复用现有 `ScenarioQueryResult` 错误映射。
- C-2：从 `PENDING_HANDLERS` 移除这 9 项；保留 `gsc.*` 6 项。
- C-3：打包后 IPC 读回验收：9 个方法在安装包里各返回一次 `ok` 结果（合成项目），脚本进 CI 的 Windows 打包检查（沿用 `#480` 的 `--run-job` 模式）。
- C-4：版本号、发布（由 lead 在 §7 的发布门通过后指令执行）。

### 4.4 D · UI 项目页面（`packages/ui/src/pages/`）
- D-1 SEO 行抽屉新增分段：**页面简报**（`pageBrief`）、**问题候选**（`issueCandidates`）、**内链上下文**（`internalLinkContext`）。
- D-2 产品管理行抽屉新增：**变更记录**（`changes`）、**SKU 简报**（`skuBrief`）、**父子归并建议**（`groupFamily`，只读展示）。
- D-3 EDM：**候选清单**（`candidates`）、**缺图清单**（`mediaGaps`）、**发送前安全检查**（`campaignSafety`）作为 EDM 页内一个抽屉入口，从页头"更多"打开。
- D-4 所有入口在能力缺失（`PENDING_HANDLERS` 或接口缺失）时**整体隐藏**，不显示"尚未接入"警告。
- D-5（A1）GSC 卡片收为"暂未开放"一行。
- 每个入口：空态、加载态、错误态各一；错误态用共享 `ApiErrorNotice`。
- 不得改：页面骨架、Tab、KPI、工具栏（留给 7.5）。

### 4.5 B · UI 共享层（`packages/ui/src/components/**`）
- B-1：7.0 期间**只做 7.5 的 W0 规范**（§5 G7.5-0），不改业务页。
- B-2：如 D 需要共享"抽屉分段容器"，B 提供，不得由 D 自建。

### 4.6 E · 验收
- E-1：按 §6 的 G7.0 验收矩阵执行：合成项目全链路 + 打包 IPC + 真实环境脱敏结论。
- E-2：只报告，不修复；新问题按手册 §5 分类后由 lead 决定。

## 6. 范围内缺陷、性能线与回滚

- 缺陷分类、处理流程与 bugfix workflow 全部见手册 §5，本文不重复。
- **性能线**（超过才算"数据错误之外的范围内缺陷"）：9 个查询方法在合成 1 万 SKU / 5 万页面下单次 ≤ 2s；SEO 页面表首屏渲染 ≤ 1s（`ui:check` 记录，不做阻断以外用途）。
