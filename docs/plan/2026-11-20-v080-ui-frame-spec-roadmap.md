# SiteIndex · v0.8.0 Roadmap：页面外框、导航与表格规范统一（2026-11-20）

> 基线：`v0.7.6`（2026-11-20 发布，main `833784e`；v0.7.6 为项目数据增强，不涉及页面外框，本文以 v0.7.5 起的界面为现状）。本文为 `v0.8.0` 的唯一执行计划，**由用户授权作为 v0.8.0 纳入目标模式**：lead 按本文执行，不视为"扩大范围"；执行流程、合并门槛、汇报与缺陷规则仍以 `docs/plan/2026-11-18-v07-lead-playbook.md` 为准（本文第 6 节列出对手册的唯一补充）。
> 仓库公开：测试、截图、fixture 一律只用虚构域名与合成数据。

## 0. 反馈来源与根因

用户在 v0.7.5 上给出三张截图和一组需求。三类问题的共同根因是同一个：**没有"页面外框"规范**——页面顶部空间、项目标识、页头按钮、表格工具栏的间距都由各页自己决定，所以每次改一页，别的页面又不一致。

| 现象 | 根因（读码） |
|---|---|
| 顶部一行"项目名 域名 平台 最近运行"占一整行，且和项目导航分成两行 | `project-header.tsx` 有身份行（`si-project-header-row`，高 44px）加 Tab 行两层；身份信息与导航无关，应属于侧栏 |
| 设计、README、运行、设置页顶部空间与其他页不一致 | `.si-content` 顶部有 `--space-7` 内边距，而 `ProjectHeader` 用负的 sticky `top` 补偿；部分页（`content`、`project-settings-categories`）又自己用 `calc(100vh - …)` 和负 margin 去抵消，其余页没有，导致各页顶部距离不同 |
| 筛选标签、搜索框、筛选按钮上下挤在一起；页头按钮小、间距小 | 页头按钮用 `small`（28px）、`gap: var(--space-2)`（8px）；工具栏各区块之间没有统一的纵向间距 token |
| 设计页：主色板缺 HEX；按钮规范区留白过大 | `DesignPage` 只展示 `rgb(...)`；"未识别"的按钮变体仍占满整块高度的空态 |
| InfoTooltip 文字超出气泡 | `.si-info-tooltip-content` 没有 `overflow-wrap`，`%APPDATA%\…\settings.json` 这类无空格长串不会折行 |
| 项目中心、Skill 中心、设置等全局页顶部与项目内页面不同，彼此也不一致 | 全局页使用 `PageHeader`（`min-height: 64px`），项目页使用 `ProjectHeader`，两套顶部各自维护 |
| 中文字体不如之前清晰 | 见第 1 节 |

## 1. 字体：建议与验证

### 1.1 建议
`--font-sans` 改为：

```css
--font-sans: "Geist Variable", "Microsoft YaHei UI", "PingFang SC", "Source Han Sans SC", sans-serif;
```

含义：英文和数字仍用 Geist（保持你上一轮的要求）；**中文在 Windows 用系统自带的微软雅黑 UI，在 macOS 用苹方**；随包的思源黑体降为最后的兜底（缺字体或 Linux）。

### 1.2 为什么
- 当前栈把随包的 Noto Sans SC（思源黑体同设计）排在系统字体之前，中文全部走它。该字体是**可变字体，没有为小字号做屏幕栅格优化（hinting）**，Windows 上 12px 渲染会偏软偏虚。
- 微软雅黑 UI 是 Windows 专为小字号界面文字做过 hinting 的字体，12px 是它的设计尺寸，笔画更实。
- `-webkit-font-smoothing: antialiased` 只在 macOS 生效，Windows 上无作用，不能指望它改善清晰度。
- 副作用：雅黑 UI 只有常规和粗体两档。**界面只用 400 与 600（渲染为粗体）两档字重，不使用 500。** 

### 1.3 验证（本文无法替代的部分）
我无法在 Linux 环境里看到 Windows 的实际渲染，所以这是基于字体特性的建议，不是已验证的结论。必须在 Windows 上对比后才定：
- **C** 在 W0 修改 token，不动其他文件。
- **E** 在 Windows 本机分别以系统缩放 100%、125% 截取同一批页面（项目中心、产品管理、SEO、设置）的"旧栈 / 新栈"对照图，只报告差异观察。用户于 2026-11-20 明确决定本版不验收 150%；不得将其记录为通过。
- **你**看对照图或测试 v0.8.0 候选包，确认清晰度。不满意则回退 `--font-sans` 一行即可。
- 本版**不删除**随包字体；是否删除（可减约 4.3 MiB 安装包体积）留到下一版，由你决定。

## 2. 版本目标与非目标
- **目标**：①统一页面外框（全局页与项目页）；②项目标识迁入侧栏；③统一页头按钮与表格工具栏的尺寸和间距；④统一表格列顺序并把 SKU 单列放首列；⑤修复设计页与 InfoTooltip 的指定问题；⑥把以上写成规范并更新 `AGENTS.md`、`docs/DESIGN.md`，用 `ui:check` 固化。
- **非目标**：新功能；数据与契约变更；按钮配色改版；其他页面结构重构；删除随包字体。

## 3. 规范（本节是规范正文，B 在 W0 原样写入 `docs/DESIGN.md`，数值只可在 §7 的 G8.0-0 内用实测下调严格度）

### 3.1 页面外框 `PageFrame`
所有页面只允许两种外框，由 B 提供共享组件，页面不得自行设置顶部距离、`calc(100vh - …)` 或负 margin。

| | 全局页（项目中心、Skill 中心、定时任务、设置、新建项目向导） | 项目页（项目内全部页面：概览、待办、产品管理、SEO、内容、EDM、设计、README、运行、设置各子页） |
|---|---|---|
| 顶部 | 页面标题行：高 56px；上内边距 `--space-6`（24px）；**不吸顶** | **项目头紧贴标题栏下沿，上内边距 0；吸顶（sticky）** |
| 顶部内容 | 标题（`--fs-page-title`）、可选标题旁 `InfoTooltip`、右侧页面操作 | 项目导航 Tab（左）+ 页头操作（右），**单行，高 48px** |
| 项目标识 | — | **不在页头出现**，见 §3.2 |
| 页面内容起点 | 标题行下 `--space-4`（16px） | 项目头下 `--space-4`（16px） |
| 水平内边距 | `--space-6` | `--space-6` |

**滚动规则（所有页面唯一）**：
1. 含 DataTable 的页面：窗口、内容区**都不滚动**，只有表格体内部滚动；页面滚动条出现即为缺陷。
2. 不含表格的页面（README、设计、设置、运行等）：项目头吸顶不动，**只有项目头下方的内容区滚动**。
3. 同一页面只允许一个纵向滚动容器。

### 3.2 项目标识迁入侧栏
- 项目页头**删除**"项目名 · 域名 · 平台 · 最近运行 · 状态 chip"整行。
- 侧栏项目项改为两行：
  - 第一行：项目名（`--fs-body`，600 字重，单行省略）。
  - 第二行（浅灰、`--fs-caption`，单行省略）：`平台 | MM-DD HH:mm`。示例：`Magento 2 | 11-20 13:39`。平台显示名取自项目数据 `platform` 经共享映射得到，**映射里没有的平台原样显示，不得臆造版本号**；运行时间使用共享 `formatDateTime`，无记录显示"未运行"。
  - 域名不再显示在页面上，放在侧栏项目项的 `title`（悬停）与项目设置页。
  - 原项目头里的"存储位置警告"迁为侧栏项目项右侧的警告图标（悬停说明），并在概览页保留一条 `Notice`；原 `projectStatus` chip（如"SEO 页面：414 个""设计规范已提取"）取消，其中有行动价值的信息并入对应页面的 `SummaryLine`，其余删除。
- 数据均已在 `ProjectSummary`（`platform`、`sync.at`）中，**无需契约变更**；只扩展 `SideNavProject` 这一 UI 类型。

### 3.3 项目页头：导航与操作区
| 项 | 规范 |
|---|---|
| 行高 | `--project-header-height`: 48px；底部 1px 分隔线 |
| 导航 Tab | 字号 `--fs-sub-title`（13px）；左右内边距 `--space-3`（12px）；Tab 间距 `--space-1`；当前项主色 + 2px 底部指示线；窄窗口收纳到"更多 ⋯"（沿用 v0.6.1，不得横向滚动） |
| 页头按钮 | 高度 `--control-height`（**32px**，不再用 28px small）；左右内边距 `--space-3`；图标 16px，图标与文字间距 `--space-2`；字号 12px |
| 按钮间距 | `--space-3`（**12px**） |
| 按钮数量 | ≤1 主 + ≤2 次 + "更多 ⋯"（沿用 v0.6.0） |
| 与 Tab 的最小间距 | `--space-4`；不足时按钮先收纳进"更多" |

### 3.4 表格上方的纵向节奏与控件
自上而下四个区域，**区域之间统一 `--space-section-gap`（12px）**，不得靠各页私有 margin 调整：
1. `SummaryLine`（可选，单行）
2. 已选筛选标签行（**仅有筛选时出现**；标签高 28px，标签间距 `--space-2`；该行上下各留 12px，因此出现与消失时不让上下元素贴住）
3. 工具栏：左 搜索（宽 280px）+ 筛选；右 视图开关 + 列设置 + 结果计数。**所有控件高 `--control-height`（32px），控件间距 `--space-2`（8px）**，工具栏行高 32px；筛选超过一行时折叠
4. 表格

### 3.5 表格列标准
1. **列序（自左至右）**：选择框 → **标识列** → 名称/标题列 → 状态类列 → 度量类列 → 时间类列 → 右侧固定操作列。
2. **标识列**：有 SKU 的表格，**SKU 单独成列放在最前（选择框之后）**，等宽字体（`--font-mono`），宽 120–160px，单行不换行，**左侧固定（sticky left）**；其后单独一列"产品名称"（含缩略图）。父子 SKU 视图中父行显示父 SKU，子行缩进显示子 SKU。SEO 表的标识列为"页面"（标题 + URL 两行）。
3. **对齐**：文本左对齐；数字、价格、百分比**右对齐**并使用等宽数字（`font-variant-numeric: tabular-nums`）；表头对齐方式与列内容一致。
4. **宽度**：沿用 DataTable 列宽契约（`width / grow / minWidth`）；任何单列默认宽度不超过表格宽度的 40%；时间列统一 140px。
5. **列设置**：次要列默认可隐藏；标识列与操作列不可隐藏。

### 3.6 其他控件
- **InfoTooltip**：气泡 `max-width: min(240px, 可用宽度)`；`overflow-wrap: anywhere`、`word-break: break-word`；使用 Radix 的碰撞避让（`collisionPadding` ≥ 8px）；路径、URL 等长串必须在气泡内折行，不得溢出。
- **设计页**：主要颜色角色卡**同时显示 HEX 与 RGB**，提供"复制 HEX""复制 RGB"两个按钮（已复制状态沿用现有反馈）；按钮规范区中"未识别"的变体收为**一行**"未识别此按钮变体"，不再占整块高度。
- **对话框、抽屉**：不在本版改动。

### 3.7 `ui:check` 新增断言（违反即失败）
| 断言 | 阈值 |
|---|---|
| 项目页：项目头顶边距视口内容区顶边 | 0px（±1） |
| 项目页：项目头高度 | 48px（±1） |
| 项目页：页头按钮高度 | 32px（±1）；相邻间距 12px（±1） |
| 项目页：各页面内容起点距项目头底边 | 16px（±1），**所有项目页一致** |
| 全局页：标题行高度与上内边距 | 56px / 24px（±1），所有全局页一致 |
| 含 DataTable 的页面：`document` 与内容区纵向滚动 | 不出现 |
| 工具栏：搜索框、筛选按钮高度；相邻间距 | 32px；8px（±1） |
| 筛选标签行存在时：与上下相邻区域的间距 | ≥ 12px（±1） |
| 带 SKU 的表格：首个数据列表头文字 | "SKU" |
| InfoTooltip：气泡内文字不超出气泡边界 | 对页面内所有 tooltip 触发后检测 |
| 项目页头内不出现域名文本 | 0 |

## 4. 其余"小样式问题"的处理规则（防止无限扩大）
用户要求"检查时一并处理小样式问题，禁止无限制扩大修复范围"。本版用**冻结清单**处理：
1. **W0 由 B、D、E 各做一次审计**：只审"可测量违例"——间距、对齐、尺寸、重叠、溢出、截断——并且必须能对应到本文 §3 的某一条规范；"我觉得更好看"一律不收。
2. 每条记录：页面、截图、对应规范条款、归属目录。
3. **总数上限 20 条**；超出则按"遮挡内容 > 文字被截断 > 对齐/间距偏差"排序截断。
4. 清单经 lead 审核后**冻结**，写入 `docs/plan/2026-11-20-v080-audit-freeze.md`；**冻结后新发现的一律进 backlog**，不得追加。
5. 清单里的每一条按 playbook §5.4 的修复流程执行（一个 PR 一条，≤ 200 行）。

## 8. 风险与处理
| 风险 | 处理 |
|---|---|
| 外框改造一次影响所有页面，回归面大 | 先合 `PageFrame`（G8.0-1），再按页迁移；每页迁移 PR 附 `ui:check` 与截图；任何页面的 DataTable 滚动回归按 R 类缺陷处理 |
| 新字体栈在你的机器上并未更清晰 | 单行 token 回退；本版不删除随包字体 |
| 侧栏两行项目项在窄侧栏被截断 | 单行省略 + `title` 完整显示；不得换行 |
| 审计清单被不断追加 | §4 冻结规则；追加请求一律 backlog，lead 不得批准 |
