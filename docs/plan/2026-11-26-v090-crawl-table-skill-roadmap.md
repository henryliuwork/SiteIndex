## 0. 反馈、现象与已核实的根因

"已核实"= 在代码或运行中直接看到；"待核实"= 由 W0 复现确认，**未复现前不得改代码**。

| # | 反馈 | 结论 |
|---|---|---|
| 1 | 每日同步显示成功，但最近上架的产品没有进入产品管理和 EDM，sitemap 里有（用户 11-27 补充） | **最高优先级**。已核实：①**SKU 库只来自每日同步的 feed**，sitemap 只用于每周的 SEO 页面抓取，两者之间没有任何对账；feed 缺品时系统不提示（结构性缺口）；②每周抓取按 sitemap 文件顺序截断到 `max_pages`（默认 2000），新品通常在 sitemap 末尾，被截断时**没有计数也没有提示**（`weekly.ts` `slice(0, maximum)`）；③feed 解析静默丢弃缺 id、重复 id、缺价格或缺链接的条目，丢弃计数没有写入运行记录；④同步结束后界面不刷新产品、库存、EDM 列表；⑤移除比例保护会让整次同步中止（这与"运行显示成功"不符，已基本排除）。**真因（feed 本身没有这些新品，还是被丢弃，还是被截断）尚未确认**，见 §3.1 的诊断与对账 |
| 2 | 产品管理、EDM 搜索框输入一个字符就出结果，焦点丢失，很难输入 | **EDM 已复现**（本地 mock，`packages/ui`）：搜索词进入查询键，每敲一个字符就重新查询，查询期间整张表（含搜索框）被卸载，焦点落到 `BODY`，第二个字符输入丢失。**产品管理在 mock 下未复现**（搜索不在查询键里），需带延迟和大数据量复现。共享 `SearchInput` 另有两个问题：防抖仅 50ms；每次变化后用已裁剪的值回填草稿，快速输入时会覆盖尚未提交的字符；没有处理中文输入法组合输入 |
| 3 | 很多页面排序标识可见但点击无效；需要持久化 | **已核实（mock 数据）**：定时任务 6/6 列、待办 5/5 列、设置分类/文件页 2 列、EDM"手动输入的首图 URL"列点击后行序不变；产品管理、产品变体、SEO 页面表、内容表有效。原因是 DataTable 使用 `manualSorting`，排序必须由页面自己应用，没有页面级保证。**"N"在数据值相同时可能是假阴性，W0 用有区分度的数据复核**。排序状态目前只在 `useState`，没有持久化；已有同类机制（`useTablePageSize` 走 `api.uiState` + localStorage）可复用 |
| 4 | 新增 Skill：agent 里输入 CDN 图片链接，写入对应产品的"手动输入首图 URL"，未明确时默认父 SKU | **已核实**：现有 `sku-media-enrich`（v1.1.0）要求精确匹配 SKU 或 handle，父 SKU 是分组规则生成的虚拟 SKU、不在 `skus.jsonl` 里，agent 会判为"无匹配"而不写入；应用内的 `edm.setManualImage` 对父 SKU 的处理是"展开到全部子 SKU 并各写一行 `main`"。Skill 要和这个行为一致 |
| 5 | 表格样式仍有问题，放到下一轮 | 见 §4。以下是我用本地 mock 走查得到的**候选**，由 B/D 在 W0 用 4 视口复核后冻结 |

## 2. 目标与非目标

**目标**：①**新上架的产品必定进入产品管理和 EDM，或在待办里明确列出未入库的原因**；同步与抓取的丢弃、截断、中止都有可见计数；同时审计其他核心抓取功能（§3.1）；②搜索输入不丢焦点不丢字；③所有可排序列点击必有效，排序状态持久化；④新增首图 Skill 与 CLI 子命令；⑤表格走查冻结清单清零。

**非目标**：新抓取源；改动移除比例保护的默认值；改动按 handle 合并的数据模型；新页面；放宽任何 `ui:check` 阈值；设置页拆分。

## 3. 规范与交付

### 3.1 核心抓取可靠性与产品发现（A 牵头，E 配合，最高优先级）

**数据来源事实**（`docs/ARCHITECTURE.md` §6）：daily = feed → SKU/库存/事件 → 视图；weekly = sitemap → SEO 页面/问题/内链/博客/产品页详情/分类页。**产品管理与 EDM 只读 SKU 库，SKU 库只来自 feed。**

**已核实缺陷（D 类，必修，红色测试先行）**

| ID | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| B1 | 每周抓取静默截断 | `weekly.ts` 按 sitemap 文件顺序 `slice(0, max_pages)`，默认 2000；新品多在末尾；截断没有计数也没有提示 | 触及上限时按 `lastmod` 新到旧保留（P8）；`counts` 增 `sitemap_urls`、`crawled`、`truncated`；截断时状态为 `partial` 并给一行说明；设置页"每周最多页面"加 `InfoTooltip` 说明默认值与截断行为 |
| B2 | feed 条目静默丢弃 | `toSnapshot` 丢弃 `no_id`、`duplicate`、`missing_price_or_link`，feed 模式下计数未进运行记录 | `counts` 增 `feed_items`、`written`、`new_sku`、`dropped_no_id`、`dropped_duplicate`、`dropped_missing_price_or_link`；运行页在有丢弃时显示一行数量 |
| B3 | 同步后界面不刷新列表 | `project-queries.ts` 只失效项目摘要；产品、库存、EDM 列表缓存 30 秒 | 任务结束后失效该项目的产品、库存、EDM、SEO、内容查询 |
| B4 | 无对账 | SKU 库与 sitemap 产品页之间没有比对 | 见"产品发现" |

**产品发现（feature，需用户确认 P7；确认前只做诊断与对账，不做入库）**
- 每周 `pages` 步骤后做对账：`page_type = product` 且状态 200 的页面，按规范化 URL 与 handle 匹配 `skus.jsonl`；未匹配的为"未入库产品"。
- 展示：产品管理摘要行增加一个可点击项"未入库 N"，点击筛出该列表，不新增 Tab；待办规则 `catalog_gap`（高）；运行记录 `counts.catalog_gap`。
- 入库（P7）：对未入库页面使用 `product_details` 已解析的 JSON-LD（名称、SKU、价格、库存状态、图片）生成 SKU 行，标记 `source: "page"`，库存状态标为未经校验；feed 后来包含同一 SKU（按 sku 或 URL）时由 feed 行接管并去掉 `source`。拿不到 SKU 或价格的页面不入库，只进待办。字段以 `DATA_SPEC.md` 必填项为准，缺必填不入库。
- 契约：`source` 为可选字段，走单独的 `contract/v090-sku-source` PR，并同步 `DATA_SPEC.md` 与 `schemas/`。

**诊断（A，先于任何修复，红色测试先入库）**：用合成 feed 与合成 sitemap（本地 HTTP 服务，`.example.test`）覆盖：

| C3 | 新品在 feed 但缺价格 |

### 3.2 搜索输入（B 改共享，D 迁移页面）

- S-1：输入过程中输入框不失焦、不丢字符、不被回填覆盖。
- S-2：防抖 250ms；中文输入法组合输入期间不触发；Enter 立即触发；清空立即触发。
- S-3：草稿保存原始文本，查询时才裁剪；空格可输入（沿用 v0.8.2 的 I8）。
- S-4（全站规则）：**数据刷新不得卸载含输入控件的容器**。查询键变化时使用 `keepPreviousData`，表格与工具栏保持挂载，仅表体显示加载状态。适用所有使用 `SearchInput` 的页面。
- 测试：对每个使用 `SearchInput` 的页面，用 100ms 间隔输入 "abc"，在查询延迟 0/300/1000ms 下断言：值为 "abc"，`activeElement` 仍是该输入框，页面不出现整表加载态闪现。

### 3.3 表格排序与持久化（B 写共享，D 迁移，A 核对列表 API）

- T7：**可排序列点击必有效**。要么点击后行序变化且 `query.sort` 更新，要么该列不渲染排序标识（`enableSorting: false`）。
- 审计：W0 列出所有 DataTable 的每个可排序列，用有区分度的数据逐列验证，形成矩阵；每列处理为"修好"或"去掉标识"，不得留"无效但可点"。
- 客户端分页的页面必须在**分页前**排序；服务端分页的页面把 `sort` 传给 API，非法字段忽略并不报错。共享提供一个 `sortRows` 辅助，页面不得各写各的。
- **持久化**：键为（设备、项目、`tableId`），值为 `{field, dir}` 或空；复用 `api.uiState`（桌面）与 localStorage 兜底，与 `useTablePageSize` 同机制。
  - 首次渲染同步读取已存值，不闪烁；异步来源就绪后应用时不重挂载表格。
  - 已存列不再存在时忽略并清除；跨项目互不影响；全局页（定时任务、项目中心）使用设备级键。
  - 一页多表（SEO 3 个、产品管理 2 个、内容 2 个）按 `tableId` 独立保存。
  - 只持久化排序，不持久化搜索、筛选、页码。
- 三态点击见 P2。
- `ui:check` 新增断言 T7：对每个 `hasTable` 路由、每个排序按钮点击两次，行序必须变化；用有区分度的 demo 数据。

### 3.4 产品首图 Skill（C 牵头，A 配合 CLI）

**交付**：
1. 新 Skill `siteindex-edm-manual-image`（目录 `skills/`，1.0.0）。
2. CLI `siteindex edm set-image <p> --sku <sku> --url <url> [--only-child]`，调用 `setManualImage`，返回写入的 SKU 列表、替换前的旧值（若有）。
3. `sku-media-enrich` 升 1.2.0，图片部分指向新 Skill；README 自动区块的 Skill 映射和 Skill 中心 mock 同步。

**Skill 规则**：
- 输入：用户在 agent 中给出一个或多个图片链接（Mailchimp CDN 或其他 CDN），可带 SKU、handle 或产品名。
- 目标解析顺序：用户明确的 SKU → 用户明确的 handle → 产品名唯一匹配；**多个匹配或没有匹配则停止并请用户确认，不猜**。
- 默认写入父 SKU（D26、P4）：解析到父 SKU 后，由 CLI 展开为全部子 SKU 各写一行 `main`；用户明确说仅此变体才用 `--only-child`。
- 链接必须是用户提供的有效 http/https，不含账号密码，不从标题构造；来源由域名判定（Mailchimp 记 `mailchimp`，其他记 `cdn`），无法确认时询问。
- 已有手动首图被替换时，报告"旧值 → 新值"。
- 写完执行 `siteindex views <p>` 重建视图，并报告：写入 SKU 数、替换数、未匹配和待确认条目。
- 不得把凭据、Cookie、带签名的临时链接写入台账。

**测试**：CLI 用例——父 SKU 展开、`--only-child`、非法 URL、未知 SKU、重复执行幂等；Skill 结构测试（frontmatter、reads/writes 与 CLI 能力一致）；README 映射与 Skill 中心列表包含新 Skill。Skill 的 agent 行为由用户在 G9.0-3 手动试用一次。

## 6. 对 playbook 的补充

1. 新品不出现是 D 类，**最高优先级，A 先做**；未复现、红色测试未入库前不得改代码；若真因是 P6，汇报用户，不自行改行为。
