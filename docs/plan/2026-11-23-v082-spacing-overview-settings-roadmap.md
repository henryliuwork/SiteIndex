## 2. 版本目标与非目标

**目标**
1. 建立可自动检查的**间距规范**，让同类问题无法再合并进 main。
2. 重做顶部 Tab 指示样式；统一页头按钮显示规则。
3. 概览页模块化（6 个模块）。
4. 产品管理页逐项修复走查清单；表头"说明"标准。
5. 设置与 README 的**保存可靠性**：每个设置项保存后能读回、升级后不丢、不被空值覆盖；修复关键词空格。

**非目标**：新功能；字体改动；数据抓取逻辑；契约语义变更（除 §5 需要的最小字段，见 §5.5）；设置页拆分（沿用 D9 例外，另记 backlog）；其他页面结构重构。

## 3. 规范（本节为规范正文，B 在 W0 原样写入 `docs/DESIGN.md`；数值只可在 G8.2-0 内按实测下调严格度）

### 3.1 间距规范

**3.1.1 刻度**：间距只允许 4 的倍数 token：`--space-1`(4) `--space-2`(8) `--space-3`(12) `--space-4`(16) `--space-6`(24) `--space-7`(32)。禁止裸 px、禁止 `margin` 做组件内部对齐（用 `gap`）。

**3.1.2 语义 token（B 新增，页面只用语义 token）**

| token | 值 | 用途 |
|---|---|---|
| `--gap-inline` | 8px | 同一行内相邻控件（输入框、筛选、分段控件、图标按钮） |
| `--gap-group` | 12px | 页头按钮之间；工具栏/摘要等区域之间（= `--space-section-gap`） |
| `--gap-block` | 16px | 卡片与卡片、区块与区块 |
| `--gap-page` | 24px | 页面水平内边距；全局页顶部 |
| `--pad-control-x` | 12px | 按钮、输入框、选择框左右内边距（紧凑 8px） |
| `--pad-chip-x` / `--pad-chip-y` | 12px / 4px | Chip、摘要项、筛选标签 |
| `--pad-card` | 16px | 卡片内边距（紧凑 12px） |
| `--gap-label-control` | 4px | 表单标签到控件；标题到副文本 |

**3.1.3 组件内部间距矩阵（全部必须满足）**

| 组件 | 高度 | 内边距 | 内部间距 | 与相邻同类控件 |
|---|---|---|---|---|
| 按钮 / 输入框 / 选择框 | 32（紧凑 28） | 左右 12（紧凑 8） | 图标与文字 8 | ≥ 8（页头按钮 12） |
| 摘要项 / Chip / 筛选标签 | 28 | 左右 12，上下 4 | 标签与数字 8 | ≥ 8 |
| 分段控件 `Segmented` | 32 | 容器内 2；项左右 12 | — | 与左右相邻元素 ≥ 8 |
| 卡片 / 面板 | — | 16 | 标题与内容 12；内容块之间 12 | 卡片之间 ≥ 16 |
| 表单行 | — | — | 标签到控件 4；行与行 12 | — |
| 表格单元格 | 行高 52 / 紧凑 40 | 左右 12 | — | — |
| 弹层（筛选、菜单） | — | 12 | 项与项 8；分组之间 12 | 与触发按钮 ≥ 4 |

**3.1.4 "文字不贴边"通用规则**：任何有边框、背景色或指示线的元素，**其内部文字的外接矩形到元素边缘**：左右 ≥ 8px（Chip/按钮 ≥ 12px），上下 ≥ 4px。**Tab 例外按 §3.2 另有规定**（文字到下划线 ≥ 12px）。

### 3.2 项目导航 Tab 样式（用户决策 D10：方案 1）
- 纯文字 Tab，当前项文字加深并 600 字重，其余灰色 400。
- **指示线**：2px、品牌色、圆角 1px，**贴在项目头底边**（与 1px 分隔线重合并覆盖它），宽度 = 文字宽 + 左右各 `--space-3`（12px），**不再是文字下划线**。
- **文字垂直居中于 48px 行**；文字底边到指示线顶边 ≥ 12px。
- Tab 之间 `--space-1`（4px）；悬停时文字变深，不出现背景色；键盘焦点使用 2px 品牌色焦点环，与指示线不重叠。
- 窄窗口收纳规则沿用 v0.6.1，不得横向滚动。
- 页内分段 `Segmented` 保持现有样式，**不使用**下划线（避免与导航 Tab 混淆）。

### 3.3 页头按钮显示规则（用户决策 D12）
- 一级显示：**1 个主按钮 + ≤2 个次要按钮**（按 `DESIGN.md` §3 的页面按钮表）；其余进"更多 ⋯"。
- **只有可用宽度不足时才收纳**，收纳顺序：先次要按钮，再导航 Tab，最后主按钮永不收纳。1280×800 起必须完整显示该页的主按钮与全部次要按钮。
- 收纳以**实测宽度**判断，不使用固定断点；按钮高 32、间距 12、左右内边距 12（修复 `project-header.css` 中 `--space-1` 的残留规则，如确实存在）。
- 每个页面的按钮清单见 `DESIGN.md` §3 表；本版新增的页面按钮（概览）见 §3.4。

### 3.4 概览页（用户决策 D11）
自上而下：项目头 → **模块网格**（不使用 `SummaryLine`，概览是首页，仍保留卡片）。网格 1280 宽 2 列、≥1600 宽 3 列，卡片间距 `--gap-block`。

| 模块 | 内容（每个模块最多 4 个数字 + 最多 3 行列表） | 点击 |
|---|---|---|
| 待办 | 未完成数、本周到期数；最近 3 条未完成待办 | 标题进待办页；每条进待办页并定位 |
| 产品管理 | 在线率、今日变化、长期缺货、状态波动 | 每个数字进产品管理并应用对应筛选 |
| SEO | 待处理问题、本次新增、未收录 | 每个数字进 SEO 并应用对应筛选 |
| 内容 | 博客文章数、最近新增篇数；关键词映射覆盖情况（如已有） | 进内容页 |
| 网站主色 | 来自设计规范：主色、辅助色、正文色，**各显示色块 + HEX**，一键复制 HEX | 标题进设计页 |
| 最近抓取任务记录 | 最近 5 条：任务名、状态、时间（`formatDateTime`）、耗时 | 进运行页；失败项标红并可进日志 |

规则：
1. 每个模块是一张卡片，**独立加载、独立空态、独立错误态**；一个模块失败不影响其他模块。
2. 同一个数字全页只出现一次；时间只出现在"最近抓取任务记录"（项目头已有"最近运行"不重复）。
3. 无数据的模块显示空态和去哪里生成数据的入口，不留空白。
4. 原有"提醒""README 摘要""更新记录"：提醒并入各模块的红色数字；README 摘要保留为末尾一张折叠卡片；"更新记录"由"最近抓取任务记录"取代。
5. 页头按钮：主"立即同步"，次"打开项目文件夹"，更多：校验本地数据文件、复制 agent 接入指令、打开 README（沿用 `DESIGN.md` §3）。
6. 所有数据来自现有接口；**确需新增字段时走 A 的 contract PR（仅 1 个）**。D 在 W0 先核实 6 个模块的数据都有来源。

### 3.5 表头说明（用户决策：产品管理页的"持续"列）
- 共享 `DataTable` 的 `ColumnDef.meta.help`：设置后，表头文字右侧显示 `InfoTooltip`（`i` 图标，14px，与文字间距 4px，不影响排序点击区）。
- **哪些列需要**：用户一眼看不出含义或口径的列（时间窗、计算口径、来源）；价格、名称、分类这种自明列**不加**。
- 产品管理页必须配置说明的列（口径文字由 D 对照 Core 实际定义写成一句话，A 复核）：
  - **持续**：当前库存状态已持续的天数（自最近一次状态变化起算）。
  - **30 天在线率**：近 30 天内有货天数占比。
  - **近 30 天趋势**：每格代表一天，颜色表示当天库存状态。
  - **最近变化**：最近一次价格、状态等事件的类型与日期。
  - **评分 / 评价数**：来源于站点商品数据，没有则显示"—"。
- 其他页面表格在 W0 由 D 列出"口径不自明"的列，按同一机制补齐，**总数上限 10 列**，超出进 backlog。

### 3.6 共享样式传播规则（用户决策 D13，写入 `AGENTS.md`）
任何修改样式的 PR：
1. 先判断该样式是否会被**多个页面**使用（grep 组件名/类名，列出使用位置）；会则**必须放进共享组件或 token**，不得写在页面私有 CSS。
2. PR 描述必须有"**影响面**"表：使用位置 → 是否已同步 → 截图。至少 3 个不同页面的前后对比截图（页数不足 3 时全部页面）。
3. 引入新规则时同步更新 `DESIGN.md` 与 `ui:check` 断言；页面私有 CSS 中出现与共享组件重复的实现，视为违规。
4. 禁止"只改被反馈的那一页"。

### 3.7 `ui:check` 间距断言（本版核心交付，违反即失败；与 v0.8.0 的 §3.7 断言并列）
所有 27 路由 × 1280×800 / 1920×1080 执行；基线机制沿用 `frame-baseline.json` 的做法，新增 `spacing-baseline.json`（逐路由登记现存违例，**只减不增**，迁移一页就必须删除该页条目）。

| 断言 | 规则 |
|---|---|
| S1 控件高度 | 所有可交互控件（按钮、输入框、选择框、Chip 按钮、分段项）高度 ∈ {28, 32}；表格内行操作除外 |
| S2 控件内边距 | 按钮/输入框/选择框 左右内边距 ≥ 12（紧凑 ≥ 8）；Chip ≥ 12×4 |
| S3 相邻控件间距 | 同一行内相邻可交互元素的外接矩形间距 ≥ 8（页头按钮 = 12）；`Segmented`、按钮组内部连接处除外 |
| S4 文字不贴边 | 有边框/背景/指示线的元素，文字外接矩形到元素边缘：左右 ≥ 8、上下 ≥ 4（Tab 为文字到指示线 ≥ 12） |
| S5 区域间距 | 摘要、筛选标签、工具栏、表格之间 ≥ 12；卡片之间 ≥ 16 |
| S6 无相贴块 | 两个同时带边框或背景的同级块，间距为 0 视为违规 |
| S7 裸值扫描 | CSS 中 `margin/padding/gap` 出现非 token 值（含 `px` 数字，`0` 和 `auto` 除外）即为新违规（沿用现有样式扫描，转为失败） |
| S8 Tab | 导航 Tab 指示线宽 = 文字宽 + 24（±2）、厚 2（±0.5）、贴底；文字到指示线 ≥ 12 |
| S9 页头按钮可见性 | 1280×800 与 1920×1080 下，每页主按钮与 `DESIGN.md` 表中的次要按钮全部在一级可见 |
| S10 溢出 | 任意文本被截断或溢出容器时必须有 `title`/`InfoTooltip`（沿用已有溢出检测） |

阈值只能在 G8.2-0 用实测核对后**下调严格度**并写明原因；其余阶段不得改。

## 5. 设置与 README 数据保存可靠性（用户决策 D14：数据丢失类，必须解决）

### 5.1 不变量（所有保存路径必须满足）
| # | 不变量 |
|---|---|
| I1 | **读回一致**：保存成功 ⇔ 文件已写入且重新读取的值与提交值一致。`core` 在写入后必须重新读取并比对，不一致则抛错（`WRITE_FAILED`），界面显示失败，不得显示"已保存" |
| I2 | **空值保护**：未修改的字段不得被空值覆盖。UI 只提交"被用户修改过的字段（dirty paths）"；`core` 拒绝用空值（`""`、`[]`、`null`、缺失）覆盖已有非空值，除非请求显式带 `clear: [路径…]`。"清空"必须由用户的明确操作触发 |
| I3 | **字段级合并**：`updateConfig` 对 `seo`、`brand`、`content`、`edm`、`crawl`、`schedule` 等分区做**深合并**，缺失字段保持原值，不得整块替换 |
| I4 | **陈旧写入检测**：UI 保存携带加载时文件的 `revision`（内容哈希或 mtime）；文件已变化时 `core` 拒绝并返回"配置已在别处更新"，UI 提示刷新或自动合并未冲突的 dirty 字段 |
| I5 | **无操作保存不改文件**：不修改任何字段就保存，文件**逐字节不变**（含不重排键、不改缩进、不增删换行） |
| I6 | **升级不改写用户字段**：升级、迁移、启动自检、所有任务（daily/weekly/monthly/readme/validate）都不得写入或清空"用户拥有的字段"。需要补默认值时只补**缺失**字段，且在 `site.json` 里登记 `schema_version` |
| I7 | **README 用户段**：`saveUserBlocks` 找不到对应 `##` 标题时，**在 README 末尾补出该标题段并写入**（不得静默返回）；README 重新生成（refresh）必须保留三个用户段原文；读取在标题缺失时返回空并附"段落缺失"标记，使界面可提示 |
| I8 | **输入保真**：多行文本框（关键词、竞品域名等）**以原始文本为草稿状态**，保存/失焦时才解析；关键词内部允许空格（如 `bird feeder`）、允许回车新增行；首尾空白与去重只在解析保存时处理 |

### 5.2 逐项审计矩阵（W0，A 牵头，D 配合，E 复核）
产出 `docs/plan/2026-11-23-v082-settings-persistence-matrix.md`，**每个设置项一行**：

`设置项 | 所在页面/控件 | IPC/API | 写入文件与键 | 读回路径 | 是否经 §5.1 各不变量 | 复现步骤结果（保存→重启→升级后）`

范围（封闭）：
- 项目级：项目设置页的全部区块（站点/品牌/抓取/SEO/EDM/内容/定时/Feed 等 `site.json` 各键）、分类规则（`categories`）、SKU 父子规则、README 三个用户段、待办、GSC 设置卡片（仅检查已有字段）。
- 应用级：软件设置（`settings.json`）、定时任务编辑、Agent 平台等。
- 每个项必须有结论：**通过 / 缺陷（附复现）**。缺陷中属于"数据丢失、静默不保存、被空值覆盖、升级后丢失"的，计入本版**范围内缺陷（D 类）**，按手册 §5 修复；其他问题进 backlog。
